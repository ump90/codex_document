### 工作树

Source: [Worktrees](https://developers.openai.com/codex/app/worktrees.md)

在 Codex app 中，工作树让 Codex 可以在同一项目中运行多个相互独立的任务，而不会彼此干扰。对于 Git 仓库，[自动化](24-automations.md) 会在专用后台工作树上运行，因此不会与你正在进行的工作冲突。在未使用版本控制的项目中，自动化会直接在项目目录中运行。你也可以手动在工作树上启动线程，并使用 Handoff 在线程的 Local 和 Worktree 之间移动。

#### 什么是工作树

工作树只适用于属于 Git 仓库的项目，因为它们底层使用 [Git worktree](https://git-scm.com/docs/git-worktree)。工作树允许你创建仓库的第二份副本（“检出”）。每个工作树都有仓库中每个文件的独立副本，但它们共享同一份关于提交、分支等的元数据（`.git` 文件夹）。这允许你并行检出并处理多个分支。

#### 术语

- **Local checkout**：你创建的仓库。在 Codex app 中有时简称为 **Local**。
- **Worktree**：在 Codex app 中从你的本地检出创建的 [Git worktree](https://git-scm.com/docs/git-worktree)。
- **Handoff**：在线程的 Local 和 Worktree 之间移动的流程。Codex 会处理安全移动工作所需的 Git 操作。

#### 为什么使用工作树

1. 与 Codex 并行工作，而不影响你当前的 Local 设置。
2. 在你专注于前台工作时，将后台工作排队。
3. 当你准备好更直接地检查、测试或协作时，稍后将线程移动到 Local。

#### 工作树设置

工作树需要 Git 仓库。请确保你选择的项目位于 Git 仓库中。

1.  选择 "Worktree"

    在新线程视图中，在输入区下方选择 **Worktree**。
    也可以选择一个 [本地环境](37-local-environments.md)，为工作树运行设置脚本。

2.  选择起始分支

    在输入区下方，选择作为工作树基础的 Git 分支。它可以是你的 `main` / `master` 分支、功能分支，或带有未暂存本地变更的当前分支。

3.  提交你的提示

    提交任务后，Codex 会基于你选择的分支创建 Git worktree。默认情况下，Codex 会在 [“detached HEAD”](https://git-scm.com/docs/git-checkout#_detached_head) 状态中工作。

4.  选择继续工作的地方

    准备好后，你可以继续直接在工作树上工作，或将线程 hand off 到你的本地检出。向 Local 或从 Local hand off 会移动你的线程和代码，因此你可以在另一个检出中继续。

#### 在 Local 和 Worktree 之间工作

工作树的观感与本地检出很相似。区别在于它们在你的流程中的位置。你可以把 Local 理解为前台，把 Worktree 理解为后台。Handoff 让你可以在线程的二者之间移动。

在底层，Handoff 会处理在两个检出之间安全移动工作所需的 Git 操作。这很重要，因为 **Git 只允许一个分支同时在一个位置被检出**。如果你在工作树上检出某个分支，就 **不能** 同时在本地检出中检出它，反之亦然。

实践中有两种常见路径：

1. [只在工作树上工作](#option-1-working-on-the-worktree)。当你可以直接在工作树上验证变更时，这条路径最合适，例如你已经使用 [本地环境设置脚本](37-local-environments.md) 安装了依赖和工具。
2. [将线程 hand off 到 Local](#option-2-handing-a-thread-off-to-local)。当你希望把线程带到前台时使用，例如你想在常用 IDE 中检查变更，或只能运行一个应用实例。

#### 选项 1：在工作树上工作

如果你想只在带有变更的工作树上工作，请使用线程标题中的 **Create branch here** 按钮，把你的工作树转换为一个分支。

之后你可以提交变更，将分支推送到远程仓库，并在 GitHub 上打开 pull request。

你可以使用标题中的 "Open" 按钮在工作树中打开 IDE，使用集成终端，或从工作树目录执行任何所需操作。

请记住，如果你在工作树上创建分支，就不能在任何其他工作树（包括本地检出）中检出它。

#### 选项 2：将线程 hand off 到 Local

如果你想把线程带到前台，请点击线程标题中的 **Hand off**，并将它移动到 **Local**。

当你想在常用 IDE 窗口中阅读变更、运行现有开发服务器，或在你日常使用的同一环境中验证工作时，这条路径很适合。

Codex 会处理在线程的工作树和本地检出之间安全移动所需的 Git 步骤。

每个线程会随着时间保持同一个关联的工作树。如果你稍后将线程 hand 回工作树，Codex 会把它返回到同一个后台环境，让你可以从离开的地方继续。

你也可以反向操作。如果你已经在 Local 中工作，并想释放前台，请使用 **Hand off** 将线程移动到工作树。当你希望 Codex 在后台继续工作，而你把注意力切回本地其他事情时，这很有用。

由于 Handoff 使用 Git 操作，任何属于 `.gitignore` 文件的文件都不会随线程移动。

#### 高级细节

#### Codex 管理的工作树和永久工作树

默认情况下，线程使用 Codex 管理的工作树。它们被设计为轻量且可丢弃。Codex 管理的工作树通常专用于一个线程，如果你稍后把该线程 hand 回那里，Codex 会将它返回同一个工作树。

如果你想要长期存在的环境，请从侧边栏项目的三点菜单创建永久工作树。这会创建一个新的永久工作树，作为独立项目。永久工作树不会被自动删除，并且你可以从同一个工作树启动多个线程。

#### Codex 如何为你管理工作树

Codex 会在 `$CODEX_HOME/worktrees` 中创建工作树。起始提交将是你启动线程时所选分支的 `HEAD` 提交。如果你选择了带有本地变更的分支，未提交变更也会应用到工作树。该工作树 _不会_ 作为分支检出。它会处于 [detached HEAD](https://git-scm.com/docs/git-checkout#_detached_head) 状态。这让 Codex 可以创建多个工作树而不污染你的分支。

#### 分支限制

假设 Codex 在工作树上完成了一些工作，你选择使用 **Create branch here** 在其上创建 `feature/a` 分支。现在，你想在本地检出上试用它。如果你尝试检出该分支，会收到以下错误：

```
fatal: 'feature/a' is already used by worktree at '<WORKTREE_PATH>'
```

要解决此问题，你需要在工作树上检出 `feature/a` 之外的另一个分支。

如果你计划在本地检出该分支，请使用 Handoff 将线程移动到 Local，而不是试图在两个地方同时保持同一个分支被检出。

#### 为什么存在此限制

Git 会阻止同一个分支同时在多个工作树中被检出，因为分支表示一个单一的可变引用（`refs/heads/`），其含义是某个工作树的“当前检出状态”。

当一个分支被检出时，Git 会把它的 HEAD 视为由该工作树拥有，并期望提交、重置、变基和合并等操作以定义明确、串行化的方式推进该引用。允许多个工作树同时检出同一分支，会在“哪个工作树的操作更新分支引用”上造成歧义和竞态条件，可能导致提交丢失、索引不一致，或冲突解决不清晰。

通过强制每个分支只能对应一个工作树，Git 保证每个分支都有一个单一权威工作副本，同时仍允许其他工作树通过 detached HEAD 或单独分支安全引用相同提交。

#### 工作树清理

工作树可能占用大量磁盘空间。每个工作树都有自己的一组仓库文件、依赖、构建缓存等。因此，Codex app 会尝试将工作树数量保持在合理限制内。

默认情况下，Codex 会保留你最近的 15 个 Codex 管理的工作树。你可以更改此限制，或在设置中关闭自动删除，如果你更愿意自己管理磁盘使用。

Codex 会尽量避免删除仍然重要的工作树。Codex 管理的工作树在以下情况下不会自动删除：

- 有固定对话绑定到它
- 线程仍在进行中
- 该工作树是永久工作树

Codex 管理的工作树会在以下情况下自动删除：

- 你归档了关联线程
- Codex 需要删除较旧的工作树，以保持在你配置的限制内

删除 Codex 管理的工作树前，Codex 会保存其上的工作快照。如果你在它的工作树被删除后打开某个对话，会看到恢复它的选项。

#### 我可以控制工作树创建在哪里吗？

目前不可以。Codex 会在 `$CODEX_HOME/worktrees` 下创建工作树，以便一致地管理它们。

#### 我可以在 Local 和 Worktree 之间移动线程吗？

可以。使用线程标题中的 **Hand off** 在线程的本地检出和工作树之间移动。Codex 会处理在线程的环境之间安全移动所需的 Git 操作。如果你稍后将线程 hand 回工作树，Codex 会将它返回同一个关联工作树。

#### 如果工作树被删除，线程会怎样？

即使底层工作树目录被删除，线程仍可保留在你的历史记录中。对于 Codex 管理的工作树，Codex 会在删除工作树前保存快照，并在你重新打开关联线程时提供恢复选项。永久工作树在你归档其线程时不会自动删除。
